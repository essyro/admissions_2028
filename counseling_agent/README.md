# 로컬 입시 근거 상담 에이전트

2027·2028 학생부교과·학생부종합 수시 자료를 검색하고 로컬 Ollama 모델이 근거를 인용해 답변하는 도구다. 모든 웹 사용자는 운영자가 설정한 하나의 Neo4j 인증 클라이언트를 공유한다. 이전 파일럿과 독립적으로 실행한다.

## 실행

Neo4j와 Ollama를 실행한 뒤 프로젝트 루트에서 다음 명령을 실행한다. Python 3.9 이상과 FTS5 trigram을 지원하는 SQLite가 필요하다. 현재 Python 3.14와 로컬 Ollama에서 개발했으며 추가 Python 패키지는 없다.

```sh
python3 counseling_agent/server.py --port 8770
```

브라우저에서 <http://127.0.0.1:8770>을 연다. 포트가 이미 사용 중이면 `--port 8771`처럼 다른 포트를 지정한다. 서버는 `127.0.0.1`에만 바인딩한다. 종료는 실행 터미널에서 Ctrl+C다.

1. 운영자는 아래 공용 인증 설정을 완료하고 서버를 시작한다.
2. 사용자는 오른쪽 위 **Neo4j 공용 연결됨** 상태를 확인하고 학년도·대학·모델을 선택해 질문한다. DB 비밀번호를 입력할 필요가 없다.
3. 답변의 `S1` 등 인용을 누르면 근거가 열린다. PDF 원문과 실제 페이지를 함께 확인한다.
4. **검색 실행 내역**에서 Neo4j 출처 경로, SQL 지표 조회, LLM 실행 상태를 확인한다.

## 운영자 공용 인증

서버 프로세스를 시작하는 환경에 다음 값을 설정한다. Neo4j 대상은 로컬 `http://127.0.0.1:7474`의 `admissions2028` DB다.

- `NEO4J_USERNAME`: 공용 서비스 계정명. 생략하면 `neo4j`다. 운영에는 대상 DB의 공개 자료 조회와 `CALL db.info()` 실행이 가능한 별도 읽기 전용 계정을 권장한다. 앱은 계정이나 권한을 생성하지 않는다.
- `NEO4J_PASSWORD_FILE`: 비밀번호가 들어 있는 UTF-8 Secret 파일의 경로. 저장소 밖에 두고 서버 계정만 읽을 수 있도록 제한한다. 파일 끝의 개행은 제거한다.
- `NEO4J_PASSWORD`: Secret 파일 대신 사용할 비밀번호 환경변수. 두 비밀번호 설정을 동시에 지정하면 시작하지 않는다.

이미 준비한 Secret 파일을 사용하는 예시는 다음과 같다. 계정명과 경로는 실제 운영 설정으로 바꾼다.

```sh
export NEO4J_USERNAME=admissions_reader
export NEO4J_PASSWORD_FILE=/secure/neo4j_password
python3 counseling_agent/server.py --port 8770
```

비밀번호를 채팅, 명령줄 인자, 소스 또는 Git에 넣지 않는다. 환경변수는 서버를 실행하는 프로세스에 전달해야 하며 다른 터미널의 설정은 자동 공유되지 않는다. 앱은 `.env` 파일을 자동으로 읽지 않는다.

서버는 시작 시 한 번 인증을 검증하고 공용 HTTP 클라이언트를 재사용한다. 각 그래프 HTTP 요청에는 동일한 인증 헤더가 사용되며 요청은 직렬화된다. 이는 서버 프로세스별 공유이며, 단일 영구 소켓이나 여러 서버 프로세스에 걸친 연결 풀은 아니다. 브라우저에는 비밀번호를 보내지 않고 연결·해제 API도 제공하지 않는다. 인증 변경은 운영자가 설정을 바꾸고 서버를 재시작해 반영한다.

비밀번호 설정이 없으면 **Neo4j 공용 미설정** 상태로 SQL 원문 검색과 LLM 답변만 제공한다. 설정된 인증이나 파일 읽기에 실패하면 비밀정보 없는 오류를 내고 서버 시작을 중단한다. 실행 중 그래프 조회 실패는 검색 실행 내역에 표시하며 성공으로 처리하지 않는다. 서버 종료 시 메모리의 인증 참조를 제거한다.

## 검색과 생성

- 공용 SQL: 검증 보고서의 최신 공용 SQLite 스냅샷을 `mode=ro`와 `query_only`로 연다. 원본 17개와 텍스트 근거 505개를 사용한다.
- 한글 검색: 페이지 텍스트를 요청 서버의 메모리 FTS5 trigram 인덱스에 올리고 한글 키워드 검색을 수행한다. 대학과 파일명상의 학년도 힌트로 범위를 제한한다. 임베딩이나 벡터 DB를 사용하는 버전은 아니다.
- 그래프: `admissions2028`의 해당 `owner_key`·`release_id`에서 `University → DocumentVersion ← EvidenceFragment` 경로를 탐색한다. SQL 근거와 그래프 페이지 텍스트·문서명·페이지 번호가 일치해야 경로를 사용한다.
- 질문 원문·학생 성적은 Neo4j에 보내지 않는다. 그래프 요청에는 검색된 공용 근거 ID와 소유권·릴리스 필터만 들어간다. 임의 SQL/Cypher를 LLM이 생성하거나 실행하지 않는다.
- 입결: 체크박스를 켜면 기존 2026 입결 DB에서 학생부교과·학생부종합의 개별 지표만 읽는다. 현재는 검색어가 실제 모집단위명에 포함되어야 한다. 전형·학년도·지표·집계대상·산출기준·각주·원본파일·페이지를 함께 제공한다. 학과 변경 매핑이나 병합값 합산은 하지 않는다.
- LLM: 기본 `gpt-oss:20b`, 화면에서 설치된 다른 생성 모델을 선택할 수 있다. 로컬 `http://127.0.0.1:11434/api/chat`에 근거와 질문을 보내고 JSON 답변을 받는다. 외부 API로 대체하지 않는다.
- 인용: 검색 근거에 없는 ID를 인용하거나 원문 인용이 없는 설명은 답변에서 제외한다. 인용문이 연결된 검색 근거에 실제로 있는지 공백을 제외해 대조하고, 확인된 원문을 설명과 함께 표시한다. 존재하는 문장을 인용했어도 설명이 원문을 정확히 해석했는지는 별도 대조가 필요하다.

## 현재 한계

현재 공용 릴리스는 `draft`다. 원문 표의 열·각주 관계를 검토하지 않았고, 텍스트 없는 76페이지는 검색되지 않는다. 원문 추출 품질의 추가 검토 대상은 총 86페이지다. 학년도 필터는 파일명 힌트이며 규칙 적용 학년도의 검증을 대신하지 않는다.

지원자격 판정, 합격확률, 안정·적정·상향 추천을 제공하지 않는다. 5등급과 9등급 간 직접 환산 요청은 차단한다. 일반 설명과 개별 수치의 정확성은 근거 확인이 필요하며, 프롬프트 제한만으로 모든 오답을 방지할 수는 없다. 2026 가이드북을 2027 문서로 바꾸거나 과거 입결을 2028 입학조건으로 붙이지 않는다.

학생 입력 양식·CSV/XLSX 업로드·프로필 저장·대화 이력 저장·다중 사용자 인증은 이번 실행 버전에 포함하지 않는다. 질문은 현재 요청에서만 처리하고 새 질문은 독립적으로 검색한다. '그 학과는?' 같은 후속 질문 대신 대학·모집단위를 다시 적어야 한다.

## 로컬 보안

앱은 질문·답변·비밀번호를 파일에 기록하지 않으며 HTTP 접근 로그도 남기지 않는다. Neo4j 인증 헤더는 실행 중인 서버 메모리에만 존재한다. 예외 메시지에 비밀번호나 요청 본문을 출력하지 않는다. 모델 서버·브라우저 자체의 로그나 암호 저장 정책까지 이 앱이 통제하는 것은 아니다.

Host·Origin·세션 헤더를 확인하고 등록된 해시의 공용 PDF만 제공한다. 원문을 열기 전 해시를 대조한다. 다른 사이트로 HTTP 리디렉션하지 않으며 로컬 요청에 프록시를 사용하지 않는다. 세션 헤더는 웹 요청 보호 장치이지 사용자별 인증이 아니다.

공용 DB 인증은 웹 사용자 인증을 대신하지 않는다. 현재는 로컬 접속만 허용하며 외부 다중 사용자 서비스로 배포하려면 별도의 사용자 인증·권한·TLS와 프록시 보안 설정이 필요하다. Neo4j 포트나 공용 비밀번호를 일반 사용자에게 공개하지 않는다. 모델 자원 보호를 위해 상담 요청은 한 번에 하나만 처리하며, 처리 중 들어온 추가 요청에는 HTTP 429를 반환한다. 학생별 저장소나 세션 격리는 구현하지 않았고 학생 정보는 공용 그래프에 저장하지 않는다.

## 검사

```sh
python3 counseling_agent/test_agent.py
```

검사는 기존 DB를 읽고 LLM·Neo4j는 모의 응답으로 검증한다. 공용 인증 설정, 인증 실패 시 비밀정보 비노출, 복수 브라우저의 공유 상태와 연결 변경 API 차단을 포함한다. 실제 Neo4j 연결은 운영자 설정 후 서버를 시작하고 출처 경로 조회로 확인해야 한다.
