기존 입결 DB와 제외된 파일럿은 수정하지 않았다. `admissions2028` DB에 공용 대학·문서·페이지 근거 528개 노드와 522개 관계를 적재했고 2026-10-18 검증 보고서를 확인했다. 자료는 `draft` 상태이며 학생정보는 적재하지 않았다.

## 실행과 검증

프로젝트 루트에서 실행한다. 외부 Python 패키지는 필요 없다.

```sh
python3 DATA_SCHEMA.md/test_schema.py
```

Python 3.9 이상 및 Python에 연결된 SQLite 3.37 이상이 필요하며 SQLite JSON 함수도 지원해야 한다. 스키마 검사는 독립된 `:memory:` DB를 사용한다. 그래프 적재기 검사는 임시 디렉터리와 모의 HTTP 클라이언트도 사용하며 실제 학생 DB·기존 입결 DB·Neo4j를 변경하지 않는다. 총 26개 검사 중 6개는 그래프 적재기 검사다. 실제 Neo4j 검증 결과는 별도 실행 결과로 확인해야 한다.

DDL은 각각 **비어 있는 새 DB에 한 번씩** 적용하는 초기화 스크립트다. 두 스키마를 같은 DB에 실행하지 않는다. 기존 입결 DB에 적용하지 않는다. 아직 마이그레이션·배포 명령은 제공하지 않는다. 애플리케이션은 연결을 열 때마다 `PRAGMA foreign_keys = ON`을 설정하고 활성화 여부를 확인해야 한다.

## 공용 원문 목록

2026-10-18에 `1_business_source_data`의 PDF 17개를 확인했다. 목록 도구는 이 폴더의 직속 PDF만 읽으며 다른 폴더를 탐색하지 않고 심볼릭 링크 PDF는 거부한다. 실제 디스크 경로와 NFC 정규화 파일명을 별도로 보존하고, 내용의 SHA-256과 바이트 수를 기록한다.

다음 명령은 현재 원본과 생성된 목록을 대조하며 파일이나 DB를 변경하지 않는다. Node 20에서 검증했고 외부 패키지는 필요 없다.

```sh
node DATA_SCHEMA.md/source_inventory.mjs --check
```

`--create`는 목록이 없을 때만 새로 생성하며 기존 파일을 덮어쓰지 않는다. 원본이 바뀌면 재검사가 실패하므로 변경 내용을 검토한 뒤 새 버전을 관리해야 한다. 목록은 자동 생성한 파일 상태 스냅샷이며, 검토 결과는 이후 별도 검토표와 대학정보 DB에 기록한다.

목록의 대학·문서유형·학년도·교육과정 힌트는 **파일명에서만 추출한 미검토 값**이다. 목록은 생성 당시 상태를 유지하며 적용 학년도와 개정일은 `null`이다. 이후 추출한 총 페이지 수와 본문은 별도 `source_text` 폴더에 기록한다. 건국대 2026 학생부 가이드북에는 2027 자료로 간주하지 말라는 검토 메모를 남겼다. 이 목록으로 후보나 지원요건을 자동 승인하지 않는다.

## PDF 1차 텍스트 추출

2026-10-18에 macOS PDFKit으로 17개 PDF, 581페이지를 추출했다. 원본 해시를 먼저 대조하고 문서별 JSON에 1부터 시작하는 PDF 페이지 번호를 기록했다. 원문 파일·기존 DB·Neo4j는 변경하지 않았다.

| 페이지 상태 | 건수 | 의미 |
|---|---:|---|
| `text_present` | 495 | 공백 제외 텍스트 40자 이상, 정확성은 미검토 |
| `no_text` | 76 | 텍스트 레이어 추출 결과 없음 |
| `sparse_text` | 10 | 공백 제외 텍스트 1~39자 |

이 중 경희대 2028 전형계획 68페이지와 건국대 계열별 이수추천과목 2페이지는 전 페이지가 추가 검토 대상이다. 나머지 적은 텍스트 페이지는 표지·빈 페이지일 수도 있으므로 86페이지 전부가 OCR이 필요한 본문이라고 단정하지 않는다. OCR은 아직 실행하지 않았다.

건국대 학생부위주전형 가이드북은 추출한 PDF 1페이지에서도 `2026학년도 건국대학교`로 확인됐다. 이를 2027 가이드북으로 재분류하지 않는다. 다른 문서의 개정일과 규칙 적용 학년도는 아직 본문 검토가 필요하다.

추출 결과는 `source_text/<SHA-256>.json`이며 모두 `review_status = unreviewed`, `layout_preserved = false`다. `page.string`은 표의 열·병합셀·각주 관계를 보존하지 못할 수 있다. 처리 중 CoreGraphics 경고도 발생했으므로 추출 완료를 렌더링 또는 표 내용의 정확성 보증으로 해석하지 않는다. 이 단계에서는 모집인원·성적 반영·수능최저 규칙을 DB에 적재하지 않는다.

프로젝트 루트에서 다음 명령으로 원본·추출물의 문서 연결과 페이지 순서를 재검사한다.

```sh
node DATA_SCHEMA.md/source_inventory.mjs --check-text
```

추출기를 재실행하려면 macOS와 Swift 컴파일 도구가 필요하다. 기본 REPL 실행이 실패한 환경에서도 아래 컴파일 방식은 동작했다.

```sh
build_dir=$(mktemp -d /tmp/admissions-pdf.XXXXXX)
xcrun swiftc DATA_SCHEMA.md/extract_public_sources.swift -o "$build_dir/extract_public_sources"
"$build_dir/extract_public_sources" DATA_SCHEMA.md/source_manifest.json DATA_SCHEMA.md/source_text
```

기존 추출물과 같은 결과는 그대로 보존하고, 결과가 다르면 중단한다. 다른 엔진이나 OCR로 재추출할 때는 원래 추출물을 덮어쓰지 않고 별도 출력 디렉터리를 사용한다. 명령 마지막에 `sha256:...` 문서 버전 ID를 붙이면 한 문서만 처리한다.

## Neo4j 공용 근거 적재

현재 적재 계획은 대학 6개, 문서 버전 17개, 텍스트가 있는 페이지 근거 505개다. 노드는 총 528개, 관계는 `HAS_DOCUMENT` 17개와 `IN_DOCUMENT` 505개로 총 522개다. 텍스트가 없는 76페이지는 빈 근거 노드로 만들지 않는다. 모두 `draft` 상태이며 모집조건·권장과목·수능최저가 검토 완료됐다는 의미가 아니다.

다음 한 줄 명령을 터미널에서 실행한다. 실행기가 비밀번호를 숨김 입력받아 같은 프로세스에서 접속·검사·적재한다. 다른 터미널의 `NEO4J_PASSWORD`는 사용하지 않으며 비밀번호를 파일·결과 보고서에 저장하지 않는다.

```sh
python3 DATA_SCHEMA.md/load_public_graph.py
```

대상은 `http://127.0.0.1:7474`의 `admissions2028` DB로 고정되어 있다. 기본 사용자명은 `neo4j`이며 다른 계정은 `--username`으로 지정한다. `--plan`은 인증 없이 읽기 전용 적재 계획만 검사한다. `--verify-only`는 숨김 인증 후 기존 릴리스만 검증하고 서버에 쓰지 않는다.

실행기는 먼저 DB 이름, 기존 `Admissions2028` 소유권, 제약조건을 조회한다. 다른 소유자의 동명 라벨이나 충돌하는 제약이 있으면 중단한다. 그 밖의 기존 노드·관계는 삭제하거나 수정하지 않는다. 공용 원문만 새 SQLite 스냅샷으로 저장한 뒤 해당 스냅샷에서 그래프 속성을 생성한다. 학생 DB와 기존 입결 DB는 읽지 않는다.

소유권은 `owner_key = admissions2028_public_sources_v1`, 릴리스는 공용 데이터 내용의 SHA-256으로 구분한다. `(admissions_id, release_id)` 고유 제약과 `MERGE`로 같은 릴리스의 중복을 방지한다. 기존 속성은 덮어쓰지 않고 기대값과 비교해 다르면 중단한다. 노드·관계 개수와 속성·관계 끝점을 데이터 트랜잭션 안에서 검증한 후 커밋하고, 커밋 후 다시 읽어 검사한다. 실패 시 데이터 트랜잭션은 롤백하지만 먼저 생성한 고유 제약은 남을 수 있다. 통신이 커밋 중 끊기면 결과가 불확실하므로 자동 재시도하지 않는다.

성공 시 `graph_staging/<release_id>.sqlite`와 `<release_id>.receipt.json`이 남는다. 보고서의 `status = verified` 및 건수를 확인해야 적재 완료로 판단한다. 로컬 계획·모의 테스트 통과만으로 실제 적재 성공을 주장하지 않는다.

## 후보 조회 경계

`v_student_record_candidates`는 다음 조건을 모두 만족하는 행만 반환한다.

- `counseling_university`에 등록된 대학. 초기 목록은 건국·경희·부산·서울·연세·중앙이다. 건국·연세의 캠퍼스는 실제 모집단위 적재 시 자료 범위대로 구분한다.
- 학년도 2027 또는 2028, 모집시기 `수시`, 전형유형 `학생부교과` 또는 `학생부종합`.
- 승인된 릴리스와 검토된 모집단위·전형·모집조합.
- 각 근거 묶음에 원문 조각이 존재하고 연결된 문서 버전도 검토 완료.

조회 도구 구현 시 이 뷰에 **현재 학생의 학년도와 선택한 릴리스 ID를 모두 바인딩**해야 한다. 여러 승인 릴리스를 한꺼번에 합쳐 상담하지 않는다. 허용 목록은 관리 설정이며 학생이나 LLM이 바꾸는 입력이 아니다. 논술·실기·특기자·정시는 저장 가능하지만 이 뷰에서는 제외된다.

전형과 모집단위가 다른 대학·학년도·릴리스에 속하면 모집조합으로 연결할 수 없다. 범위 연결과 과목 권장표에도 동일 학년도·대학·교육과정 제약을 적용했다. 미공개 모집인원은 0이 아니라 `NULL`과 별도 상태로 보존한다.

이 뷰에 노출된다는 것은 **검토된 후보 사실이 있다**는 뜻이며 지원 가능·합격 가능 판정이 아니다. 규칙, 수능최저, 과거 입결 비교 가능성은 별도 도구의 검증이 필요하다.

## 학생 과목 CSV 규격

한 파일은 한 학생의 한 프로필 버전에 해당한다. 가명·지원 학년도는 파일 밖의 프로필 입력으로 받으며 CSV에 실명·연락처·학교명·식별번호를 넣지 않는다. 다음은 업로더가 구현해야 할 매핑 규격이다. 현재 CSV를 읽어 학생 DB에 저장하는 기능은 없다.

| CSV 열 | 입력값 | DB 매핑 |
|---|---|---|
| 학교연도 | 2000~2100 정수, 예: 2026 | `student_term.school_year` |
| 학년 | 1~3 정수 | `school_grade` |
| 학기 | 1 또는 2 | `semester` |
| 과목명 | 필수, 실제 표시명 | `course_name` |
| 교과군 | 선택, 모르면 공란 | `subject_group` |
| 교육과정 | 2015 / 2022 / 미확인 | `2015` / `2022` / `unknown` |
| 선택유형 | 공통 / 일반선택 / 진로선택 / 융합선택 / 전문교과 / 기타 / 미확인 | `elective_type` |
| 이수상태 | 이수완료 / 이수중 / 이수예정 | `completed` / `in_progress` / `planned` |
| 학점 | 양수, 미확인은 공란 | `credits` |
| 석차등급 | 등급체계에 맞는 정수, 없으면 공란 | `rank_grade` |
| 등급체계 | 5 / 9 / 성취도만 / 미확인 | `5` / `9` / `achievement_only` / `unknown` |
| 성취도 | A / B / C / D / E / P / F, 없으면 공란 | `achievement` |

- 교육과정과 등급체계는 지원 학년도에서 추정하지 않는다. 2028 지원자의 2015 교육과정·9등급 기록도 허용한다.
- 5등급제는 1~5, 9등급제는 1~9의 정수만 허용한다. 성취도만 있거나 등급체계가 미확인이면 석차등급을 넣지 않는다.
- 이수중·이수예정 과목은 석차등급과 성취도가 모두 공란이어야 한다. 중간 성적을 확정 성적으로 입력하지 않는다. 이수완료 과목의 성적 미기재도 허용하며 이후 판정에서는 정보 부족으로 처리해야 한다.
- 예정 학점도 입력 가능하며, 모르면 공란으로 둔다. 빈 값을 0이나 임의 등급으로 대체하지 않는다.
- 같은 학기·교육과정·과목명의 중복은 DB에서 차단한다. 업로더는 행 번호와 오류 열을 안내하고, 충돌한 행을 조용히 덮어쓰지 않아야 한다.
- CSV는 UTF-8이며 한글이 깨지면 Excel의 '데이터 > 텍스트/CSV에서' 기능으로 UTF-8을 선택한다. XLSX 생성·읽기는 아직 구현하지 않았다.
- 업로더에서 셀 타입·열 구성·공백·한글 NFC 정규화·과목 식별자 매핑을 검증해야 한다. 파일 경로 자체는 실제 디스크 표기를 유지한다.

## 학생정보 저장과 삭제

대학 DB와 학생 DB를 분리하는 원칙은 2026-10-18 사용자 확인으로 확정했다. Neo4j와 공용 벡터 DB에는 대학 공용 정보만 적재한다. 학생 프로필·성적·상담기록과 학생별 관계·평가는 별도 로컬 학생 DB에만 영속 저장하며 공용 그래프·벡터·로그에 복제하지 않는다. 상담 중 학생-과목 비교는 요청 메모리에서만 수행한다.

학생 DB의 대학 과목·모집조합·근거 ID는 릴리스 ID와 함께 보존하며, 서로 다른 DB 사이에는 SQLite 외래키를 걸 수 없으므로 서비스에서 실제 존재와 교육과정 일치를 확인해야 한다.

`student_profile` 삭제는 버전, 성적, 시험, 선호, 업로드 오류, 상담 메시지, 후보 평가, 근거 참조, 준비 행동으로 연쇄 적용된다. 이는 **현재 DB의 논리적 행 삭제**이며 파일 복구 방지·로그·백업 삭제까지 보장하지 않는다. 파일 암호화, 로컬 접근 통제, 보관 기한, 원본 업로드와 백업 삭제 정책은 사용자 확인 후 구현한다. 스키마만으로 개인정보 보호가 완료된 것은 아니다.

수능최저는 실제 수능·모의/시나리오·미확인 근거를 분리해 저장한다. 미확인 근거로 '충족'을 저장하는 것은 차단했다. 모의고사 점수를 실제 수능으로 사용할 수 없도록 판정 도구가 입력 시험 종류를 추가 검증해야 한다. 5등급과 9등급 간 환산·직접 비교 기능은 제공하지 않는다.
